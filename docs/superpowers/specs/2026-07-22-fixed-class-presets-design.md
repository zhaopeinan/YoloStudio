# 固定六类类别预设设计

## 目标

将类别管理从“手动输入名称并逐个创建”改为“从固定六类中选择并一次启用”，降低零基础标注员的操作成本，同时保持现有项目级类别、YOLO 标签索引和历史标注数据兼容。

## 固定类别

类别名称和展示顺序固定为：

1. `fire_truck`
2. `person_white`
3. `prius_hybrid`
4. `car_lexus`
5. `prius_hybrid_camo`
6. `suv_camo`

系统按固定顺序分配展示颜色。实际训练和标注仍使用后端返回的项目类别 ID，不根据名称自行推断 YOLO 类别索引。

## 交互设计

- 类别管理页展示六个固定类别选项，每项使用可勾选的类别卡片，不提供名称输入框。
- 新项目进入类别管理页时六项默认全选。
- 已存在的同名项目类别自动显示为已启用；重复执行不会重复创建类别。
- 用户可以取消不需要的类别，点击“启用所选类别”一次性创建当前项目中缺失的选中类别。
- 未选中的类别不会被删除，也不会停用已有项目类别，避免破坏历史标注和已冻结版本。
- 现有类别列表继续展示，允许用户选择当前标注类别；已有类别的编辑能力保留，用于兼容历史项目。
- 没有任何类别被选中时，批量启用按钮禁用；接口失败时保留勾选状态并显示错误信息。
- 批量创建完成后刷新训练准备数据，选中第一个可用类别；如果这是项目的首个类别，沿用现有流程自动进入图像标注。

## 数据流与边界

前端使用现有 `POST /api/projects/{project_id}/classes` 接口逐项创建缺失类别，不新增后端接口。创建请求使用预设名称和系统颜色，后端返回的类别对象写入现有 `classes` 状态。

预设选择状态和项目类别状态分离：预设选择代表本次希望启用的固定类别，项目类别列表代表后端已经存在的类别。这样既支持批量启用，也不会因取消勾选而删除历史类别。

## 验证

- 前端测试验证六个预设名称和默认全选。
- 前端测试验证取消一项后只创建其余缺失项。
- 前端测试验证同名已有类别不会重复调用创建接口。
- 前端测试验证批量创建后进入标注页的原有工作流不回归。
- 运行前端测试和构建，并检查差异格式。
