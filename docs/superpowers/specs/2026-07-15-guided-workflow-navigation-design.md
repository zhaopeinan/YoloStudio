# YOLO Trainer 分步工作流导航设计

日期：2026-07-15

## 目标

将当前纵向堆叠所有功能的单页工作台重组为六个职责清晰的步骤页面，让首次使用者能明确知道当前任务、下一步操作和未满足的前置条件，同时保留熟练用户快速跳转到任意可用模块的能力。

本次改造只重组前端信息架构和页面展示，不修改后端 API、数据库模型、训练流程、预测流程或标注数据格式。

## 已确认结构

1. 项目与数据：扫描、导入、加载数据集。
2. 类别管理：创建、选择和编辑项目级类别。
3. 图像标注：图像筛选、选择、画框、修正和保存。
4. 质量与版本：质量审查、覆盖分析、自动标签和冻结数据集版本。
5. 模型训练：训练参数、启动、监控、日志、产物和历史记录。
6. 评估与导出：预测分析、失败样本、实验看板和模型导出。

桌面端使用固定左侧步骤导航；窄屏使用顶部步骤选择器。主内容区一次只显示一个步骤页面。

## 导航行为

### 步骤状态

每个步骤显示以下一种状态：

- `未开始`：尚无该步骤需要的数据。
- `进行中`：已具备进入条件，但核心任务尚未完成。
- `已完成`：达到该步骤的最低完成标准。
- `暂不可用`：缺少前置条件，不能进入。

状态判定：

| 步骤 | 可进入条件 | 完成条件 |
| --- | --- | --- |
| 项目与数据 | 始终可进入 | 已加载或导入数据集 |
| 类别管理 | 已加载数据集 | 至少有一个项目类别 |
| 图像标注 | 已加载数据集且至少有一个类别 | 至少一张图像有已保存标注 |
| 质量与版本 | 已加载数据集 | 至少创建一个冻结数据集版本 |
| 模型训练 | 至少有一个数据集版本 | 至少有一个训练任务 |
| 评估与导出 | 至少有一个训练任务 | 至少有一个预测任务或导出产物 |

被锁定步骤仍显示在导航中。点击时不切换页面，而是在导航附近显示具体原因，例如“请先创建至少一个类别”。

### 自动推进

- 数据集导入或加载成功后，自动进入“类别管理”。
- 创建第一个类别后，自动进入“图像标注”。
- 保存第一批标注后不自动离开标注页，避免打断连续标注。
- 创建数据集版本、启动训练和完成预测后不自动跳转，由用户通过明确按钮或导航决定下一步。

### 手动跳转

用户可随时返回已开放的前序步骤。页面切换不清空当前筛选、训练配置、选中图像或未提交的表单字段。

标注页存在未保存的边界框修改时，切换步骤前显示应用内确认提示，提供“留在标注页”和“放弃未保存修改”两个操作。已保存状态下直接跳转。

## 页面布局

### 全局外壳

顶部保留产品名称、设备状态和紧凑的工作空间信息。工作空间与数据库路径继续使用省略显示和完整路径悬停提示。

主体分为：

- 左侧导航：步骤编号、名称、状态和简短前置条件提示。
- 主内容：当前步骤标题、当前任务操作区和必要的上下文信息。
- 页面底部：可用时显示“上一步”和“下一步”操作；标注页以保存和图像切换操作为主，不重复放置通用下一步按钮。

### 移动端

在 `820px` 以下，左侧导航改为顶部步骤选择器。选择器显示当前步骤和状态，展开后列出全部步骤。主内容保持单列，标注画布和编辑器纵向排列。

## 步骤页面职责

### 项目与数据

只展示数据集路径、项目名称、数据集名称、扫描结果、导入按钮和已保存数据集加载器。后端状态以紧凑条展示，不占用独立的大型三卡区域。

导入成功后显示数据集名称、图像数和来源摘要，并提供“进入类别管理”。

### 类别管理

类别创建表单与类别列表占据主要内容。每个类别可选择、改名和改色。页面顶部显示当前项目和数据集名称；不展示图像浏览器或画布。

### 图像标注

保留现有三部分工作区：图像浏览与筛选、标注画布、边界框编辑器。项目类别改为画布顶部的紧凑类别选择器，不再占用独立侧栏。

页面顶部持续显示标注进度，例如“已标注 18 / 1099 张”。质量问题或预测失败样本跳转到标注页时，自动选择目标图像并保留对应审查叠加层。

### 质量与版本

质量指标、问题样本、数据集覆盖情况和版本导出放在同一页面，因为它们共同回答“当前数据是否可以冻结用于训练”。创建版本前明确显示阻塞问题和所选类别子集。

### 模型训练

训练设置与训练记录放在同一页面。活跃训练任务固定在记录顶部，自动刷新状态、日志和产物。实验看板不在此页展示。

### 评估与导出

预测分析、预测任务、失败样本、实验看板和模型导出集中展示。点击失败样本的“打开图像”后切换到图像标注页，并加载预测审查状态。

## 前端架构

不引入 React Router。现有 `App` 继续拥有共享业务状态和 API 调用，新增一个轻量页面状态：

```ts
type WorkflowStep =
  | "dataset"
  | "classes"
  | "annotation"
  | "quality"
  | "training"
  | "evaluation";
```

新增职责明确的展示组件：

- `WorkflowShell`：全局顶部栏、桌面导航和移动步骤选择器。
- `WorkflowNavigation`：步骤状态、锁定原因和点击处理。
- `DatasetStep`、`ClassesStep`、`AnnotationStep`、`QualityStep`、`TrainingStep`、`EvaluationStep`：承载现有 JSX 区块。

为控制本次风险，业务状态和处理函数暂不拆出 `App`。步骤组件通过明确 props 接收数据和回调，后续可再独立整理状态管理。

当前步骤保存在 URL hash，例如 `#annotation`。刷新页面时，如果 hash 对应步骤满足前置条件则恢复该步骤；否则回退到最早需要处理的可用步骤。

## 数据流

1. `App` 加载健康状态和已保存项目。
2. `App` 根据业务状态计算每个步骤的可用性与完成状态。
3. `WorkflowShell` 只渲染当前步骤组件。
4. 步骤内操作继续调用现有处理函数。
5. 数据集导入、第一个类别创建、失败样本跳转等事件更新当前步骤和 URL hash。

API 请求、自动刷新定时器和数据缓存不因页面隐藏而销毁。活跃训练和预测任务在其他步骤页面仍持续刷新。

## 错误处理

- 被锁定步骤点击后显示中文前置条件说明。
- URL hash 无效时回退到“项目与数据”。
- URL hash 指向锁定步骤时回退到当前最合理的可用步骤，并显示一次原因提示。
- 未保存标注离开确认不使用浏览器原生对话框，采用应用内确认条，保证视觉与交互一致。
- API 错误继续显示在所属步骤页面，不跨页面共享错误横幅。

## 测试

- 测试首次加载只显示“项目与数据”内容，不同时渲染其他步骤主体。
- 测试无数据集时后续步骤为暂不可用，并显示准确锁定原因。
- 测试导入或加载数据集后自动进入类别管理。
- 测试创建第一个类别后自动进入图像标注。
- 测试已开放步骤可手动往返，现有表单和筛选状态保持。
- 测试 URL hash 恢复、无效 hash 回退和锁定步骤回退。
- 测试失败样本“打开图像”切换到标注页并选择正确图像。
- 测试未保存标注切换步骤时出现确认条。
- 保持现有画框、移动、缩放、类别修改、质量审查、训练、预测和导出测试通过。
- 浏览器验证桌面侧边导航、窄屏顶部选择器、中文文字适配和页面无横向溢出。

## 验收标准

- 主内容区任意时刻只展示一个业务步骤。
- 新用户可从导入数据集自然推进到类别管理和图像标注。
- 每个锁定步骤都有明确、可执行的解锁说明。
- 标注页保留现有完整画框与修正能力，且类别选择更靠近画布。
- 活跃训练与预测任务在切换页面后继续刷新。
- 失败样本仍能正确回流到标注页。
- 桌面和移动端导航可用，中文文案无重叠或溢出。
- 前端测试、生产构建和后端回归测试通过。

## 非目标

- 不修改后端 API 或数据库。
- 不引入多用户、权限或云端导航。
- 不引入 React Router 或新的全局状态库。
- 不重写标注画布、训练执行器或预测引擎。
- 不在本次改造中拆分所有业务状态和 API hooks。
