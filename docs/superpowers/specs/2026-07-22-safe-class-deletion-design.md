# 类别安全删除设计

## 目标

允许用户清理项目中不需要且未被使用的类别，例如历史导入产生的 `train-2` 和 `train-3`，同时保护仍被标注或冻结数据集版本引用的类别。

## 删除规则

- 类别删除必须通过确认操作触发。
- 后端删除前检查该类别是否被任何标注记录引用；若有引用，返回冲突，不删除。
- 后端删除前检查该类别是否被任何数据集版本的 `class_mapping` 引用；若有引用，返回冲突，不删除。
- 未被标注且未被任何数据集版本引用的类别可以直接删除。
- 不级联删除标注、图像、数据集版本或训练任务。
- 现有固定六类批量启用和历史类别编辑行为保持不变。

## 后端接口

新增 `DELETE /api/projects/{project_id}/classes/{class_id}`。成功返回删除后的类别对象；项目不存在或类别不存在返回 404；存在标注或版本引用返回 409，并返回可读的阻塞原因。

类别列表仍返回项目中的所有类别，并额外返回 `annotation_count` 和 `version_count`，用于前端展示删除保护原因。计数按项目范围统计，避免只根据当前打开的数据集误判。

## 前端交互

- 每个类别行增加删除图标按钮。
- 删除按钮在 `annotation_count === 0 && version_count === 0` 时可用，否则禁用并显示“已被使用，不能删除”。
- 点击可删除按钮后打开确认弹窗，明确类别名称和“此操作不可恢复”。
- 确认后调用删除接口；成功后从列表移除、刷新训练准备数据，并在删除当前选中类别时选择第一个剩余类别。
- 接口冲突或失败时保留类别并显示错误信息。

## 验证

- 后端测试覆盖删除未使用类别、标注引用冲突、数据集版本引用冲突、错误项目和错误类别。
- 前端测试覆盖删除按钮状态、确认取消、确认删除及删除后列表刷新。
- 运行后端测试、前端测试、前端构建和差异格式检查。
