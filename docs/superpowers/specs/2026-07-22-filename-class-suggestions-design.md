# 文件名类别建议与负样本标注设计

## 目标

在图像标注工作台中利用文件名提供类别建议，减少标注员的选择成本，同时保留人工确认、修改和删除的权利。系统还需要明确区分“尚未处理”和“确认无目标”，以便负样本可以进入后续数据集版本与训练流程。

## 行为设计

### 文件名类别建议

- 建议只来源于当前项目类别库，不直接创建新类别。
- 匹配前统一处理大小写、空格、下划线和连字符。
- 支持有限的文件名别名，例如 `firet` 可以映射到 `fire_truck`。
- 命中一个类别时，在图像列表和标注工具栏显示“建议类别”。
- 建议只用于预选当前绘制类别，不自动生成边界框，也不自动保存标注。
- 标注员可以在框选前更换类别；已绘制的框可以继续修改类别或删除。
- 无法唯一匹配时不自动选择类别，只显示待人工选择状态。

### 图像标注状态

图像增加明确的标注状态，保存在图像元数据中，不改变 YOLO 框格式：

- `unreviewed`：尚未确认，包含当前没有框但还未保存为负样本的图像。
- `annotated`：已保存一个或多个边界框。
- `negative`：已确认图像中没有目标，保存为空标注的负样本。

保存空框时必须由标注员明确点击“确认无目标”，普通的空白画布不会自动变成负样本。已确认无目标的图像可以重新打开，添加框后自动转为 `annotated`；清空框并再次保存为无目标时转回 `negative`。

### 标注界面

- 图像列表显示文件名、建议类别和标注状态。
- 工具栏显示建议类别，并提供“采用建议”与当前绘制类别选择。
- 标注工具栏提供“确认无目标”操作；已有框时需要先清空框才能确认。
- 保存、保存并下一张、上一张和下一张继续沿用现有工作流。
- 下一张优先选择 `unreviewed` 图像，避免跳过未处理样本。

## 数据流

1. 后端图像接口返回 `annotation_status` 和文件名建议所需的相对路径。
2. 前端根据项目类别库和规范化规则计算建议，避免把推断结果写入数据库。
3. 保存标注时，前端将边界框和目标状态一起提交。
4. 后端校验类别归属后替换图像框，并保存状态。
5. 图像列表、质量统计和版本导出继续使用真实框数量；负样本以零框和 `negative` 状态参与数据集导出。

## 边界与安全

- 文件名建议永远不是人工确认的替代品，不会生成位置或边界框。
- 类别库中不存在的文件名 token 不会被写入标注。
- 多个类别同时命中时显示候选，不自动决定。
- 旧数据没有状态时按 `unreviewed` 兼容读取。
- 删除全部框不会自动确认无目标，防止误把漏标图当成负样本。

## 测试范围

- 文件名规范化、别名匹配、单一命中和多重命中。
- 图像接口返回旧数据默认状态和新状态。
- 保存有框、确认无目标、负样本重新加框的状态转换。
- 前端展示建议、修改建议、删除框和确认无目标。
- 保存失败时不改变当前草稿和状态。
